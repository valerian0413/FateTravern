# FateTravern

跑在你自己电脑上的单人跑团。主持人由大模型担任

## 玩法

打开浏览器就是一张桌。左侧是角色档案，中间的「旅途见闻」记下已经发生的事，右侧「与主持人交谈」用来说话。

旅途见闻只收录你已经做出的行动，以及世界对这件事的直接回应。商量、提问、还没点头的新设定，都留在交谈这边。

世界按自己的规矩运转。你还没看见的东西，主持人不会提前摊开。你临时补一条设定时，主持人先核对它和已有内容是否打架；你确认之后，它才写进世界。


### 先玩一场现成的

「使用说明」和「世界档案」都可以试玩「悬云海-预设」。你是见习学者云隼，为完成老师未竟的《空岛怪物指南》，搭乘飞艇前往悬云岛。飞艇正在穿越雷云层，一只云鲨突然朝船身冲来。每次开始都会创建一份新存档。

### 自己开一桌

到「创建世界」。可以选一份预设、复用已经保存的世界设定，或从一个想法写起。

左侧用短句和主持人说话，右侧是可以手改的设定表。不必一次写完整本设定集。讲清你在意的几件事就够：这是什么地方、气氛如何、有没有超凡、钱叫什么、人怎么从一个地方到另一个地方、开场时你站在哪里。空白可以留着，也可以让主持人补上，再由你改。

> 靠码头的石城，没有魔法。货币是铜贝，一枚铜贝买一顿简餐。城里走路，出城靠河船，上行要一整天，沿途有盗匪。

设定够用时，点「保存世界并创建角色」。世界设定会单独保存，然后进入角色卡。已保存的设定可以再拿来开一份新草稿，改新草稿不会覆盖原来那份。

角色用一套简化的 Fate。说你是谁、为什么出现在开场、擅长什么。技能不必自己算完，主持人会按经历填进表格，你仍可以手改：

- 两个形象：高概念，以及一个自由形象
- 十九项技能里，一个 +2、两个 +1，其余为 0
- 一条压力轨，三格，分别承受 1、2、3 点
- 伤痕三档：轻微 2、中度 4、严重 6

> 退役的河船领航员，来找失踪的弟弟。水性好，认得出天气，不太会说话。

角色卡完成后进入冒险。下次接着玩，到「世界档案」打开对应存档。

### 冒险进行中

在「与主持人交谈」里直接打字。一句短话就够，含糊的地方主持人会先问清楚。

- 问规则或商量计划，照常问。例如：这里的铜贝够不够住一晚？这类对话不推动时间，也不掷骰。
- 想让事情发生，用「我」写出具体行动。例如：我把船拴在栈桥上，先看布告板。游戏时间跟着行动走。
- 咨询时如果附带一条建议行动，要点「执行这个行动」，事情才会真正发生。
- 遇到风险或岔路，主持人给出两到四个建议。可以点，也可以自己写一句。

战斗里，攻击和防守各自掷骰，攻防的正差值就是这次伤害。挨打之前可以退让：说清你怎么退出，拿到 1 点命运点，再加这场新留下的伤痕数。一次受击最多花一格压力，也可以叠上伤痕。伤害没有被完全扛住，角色就出局。这一场结束、并且能够休息时，压力和轻微伤痕会清掉。

判定掷四枚骰，每枚是 −1、0 或 +1。四枚相加，加上技能加值，再加上情境修正（每一项 +1 或 −1），去比难度：简单 0、普通 2、困难 4、极难 6。打平算成功。形象带来的修正必须对上角色卡上真实写着的形象，并说明原因。

刷新或断线之后可以接着玩。同一轮如果已经掷过骰，重试不会重掷。

## 配置与启动

需要 Python 3.10–3.13，以及一个兼容 OpenAI Chat Completions、并且支持工具调用的模型服务。地址、密钥或模型名缺失时，启动会直接报错。

```sh
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
cp .env.example .env
```

用编辑器打开项目根目录的 `.env`，至少填这三项：
目前建议用Deepseek flash

- `LLM_BASE_URL`：模型服务地址，一般以 `/v1` 结尾
- `LLM_API_KEY`：密钥
- `LLM_MODEL`：模型名

然后启动，并用浏览器打开 http://127.0.0.1:8000 ：

```sh
.venv/bin/python run.py
```

`run.py` 读取项目根目录的 `.env`。想换一份配置，加上 `--config 文件路径`。系统里已经设置的同名环境变量优先于文件。全部变量见 `.env.example`，平时会碰到的是：

- `HOST`、`PORT`：本机地址和端口，默认 `127.0.0.1` 和 `8000`。
- `DB_PATH`：存档数据库，默认 `data/engine.sqlite3`。相对路径都放在项目的 `data/` 下，所以 `engine.sqlite3` 和 `data/engine.sqlite3` 是同一个文件；也可以写绝对路径。启动时终端会打印实际路径。SQLite 的 `-wal`、`-shm` 和迁移备份 `.bak-*` 跟数据库放在一起。
- `LOG_DIR`：模型调用日志，默认 `logs/`。
- `LLM_TIMEOUT`：单次调用最长等待秒数，默认 90。`LLM_CONCURRENCY`：同时进行的调用数，默认 4。
- `LLM_PROVIDER`：`auto` 只对官方 `api.deepseek.com` 附带 DeepSeek 专用参数。走兼容代理时设为 `deepseek`，其他服务设为 `openai_compatible`。
- `LLM_JSON_OUTPUT`：`true` 时要求模型按 JSON 对象返回。服务不支持就设为 `false`，程序仍在本地解析。
- `LLM_THINKING`：DeepSeek 的思考开关，默认 `disabled`。设为 `enabled` 时，用 `LLM_REASONING_EFFORT` 指定 `low`、`high` 或 `max`。
- `LLM_STREAM`：`true` 时页面边生成边显示文字。服务不支持流式输出就设为 `false`。
- `NARRATION_MAX_CHARS`：单段叙事的字数上限，默认 180。`PROMPT_VERSION` 是写进日志的提示词版本标记。

网络中断、请求过于频繁（429）和一部分服务端错误（5xx）最多试三次。返回空白或无法解析的 JSON 时，会再试一次。其他客户端错误（4xx）、输出被截断、内容被过滤，不再重试。每次尝试都记在 `logs/` 的 JSONL 里，密钥会打码。

可选：让主持人按意思翻查已经发生过的事。在项目目录运行下面的命令，安装约 24 MB 的中文嵌入模型，然后重启服务。

```sh
.venv/bin/python scripts/install_memory_model.py
```

第一次检索会为当前存档建索引，之后沿用。索引放在数据库旁边的 `<数据库名>.vectors/`，删掉也可以从存档重建。不想用时把 `MEMORY_VECTOR` 设为 `false`，或用 `MEMORY_MODEL_DIR` 指向已经放好模型文件的目录。模型文件缺失或检索失败时，主持人改为按关键词查找。

## 项目怎么运转

一次本机进程同时提供网页和主持。正式状态写在 SQLite：世界、角色、事实、谁看见了什么、已经提交的叙事。模型可以提议，只有提交这一步能改存档。

你发出的每一句话先判断意图：

- **咨询**：回答规则和计划，可以附一条建议行动，等玩家点「执行这个行动」。
- **澄清**：意思不够具体时先问一句。
- **共创**：新设定先审核。有冲突就给出理由和一处最小改法；玩家确认后写入，并核对提案版本和当前世界版本。
- **行动**：进入下面的行动流程。遇到成规模的冲突时，也可以开一场遭遇（战斗、交涉或追逐），按回合处理。

行动按顺序进行：计划这一步要面对什么，必要时等你选择，由程序掷骰，核对改动是否说得通，写成玩家能看见的叙事，再提交存档。骰点和难度由程序计算。讨论不推进游戏时间，也不扣资源。

遭遇中先判断行动包含哪些独立风险，再逐项选择技能、对抗技能与射程。无风险扫视不用检定，攻击与对手的闪避合为一项攻防对抗。明确授权的短复合行动可以拆成一至三个步骤，总耗时不超过一轮的 8 秒、最多一次主要攻击；依赖前一步成功的步骤会在前置失败时跳过。耗时较长的准备仍跨轮完成。技能按实际方法选择，施法与挥动法器砸击可以使用不同技能。

战斗、追逐和交涉的结算结果也交给通用叙事模块，结合已知场景写成连贯描述。叙事不决定伤害、物品消耗或位置变化；尚未选择如何承受攻击时，不提前写出新伤。结算与叙事分别保存检查点，叙事中断或提交失败后重试不会重新掷骰。

「旅途见闻」只根据已经授权的行动和玩家当时能看见的结果来写。玩家的原话、审核意见和内部推理留在交谈一侧。隐藏事实留在主持人侧，公开之后才进入你能检索的范围。

主持人可以用工具查看公开设定和已经提交的叙事。装了嵌入模型之后，检索会把关键词和语义结果合在一起。范围是当前世界里玩家可见的实体、仍然有效的事实、公开的世界书，以及已保存的叙事。回合摘要会生成并保存，目前还没有拿回来当作上下文。后台 NPC 的日程也还没有接上。

冒险由 CrewAI Flow 串起来。交互流程负责把一句话分到咨询、澄清、共创或行动；行动流程负责从计划走到提交。规则和重试读取 SQLite 里的回合记录。断线后用同一个请求编号查询或重试，已经掷出的骰子保持原结果。

通过页面创建的世界使用 `fate-lite-v1`：四骰判定加上上面的简化 Fate 角色。模型网关需要支持 Chat Completions 的工具调用。目前只能从源码目录运行（`pip install -e .`），提示词、数据库迁移和 `config/` 都按源码路径读取。

模块边界、数据结构和接口见 [docs/implementation-handbook.md](docs/implementation-handbook.md)。
